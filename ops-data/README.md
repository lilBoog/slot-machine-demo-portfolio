# 專案 06：金鯉躍門 營運資料實作

用金鯉躍門的數學模型模擬 2026 年 9 月的營運資料，示範數值機率助理的日常工作：**SQL 撈資料與檢查、Excel 例行報表、版本驗收文件**。

> 所有資料由 `build_data.py` 依遊戲數學模型模擬生成，不是實際營運數據。

## 情境

| 日期 | 版本 | 發生什麼事 |
|---|---|---|
| 9/01–9/20 | v1.2 | 正常營運。9/17 出現一次誤報（\|z\| = 3.01），9/12、9/17 各有幾筆資料品質問題 |
| 9/21–9/24 | v1.3 | 介面改版上線，但**免費遊戲倍數誤設為 ×3（規格 ×2）**，驗收時漏掉 |
| 9/21 | — | 日報 z 檢定當天警示 → SQL [Q06] 發現免費遊戲平均贏分偏高 → [Q07] 設定核對找到 `fg_mult = 3` |
| 9/25–9/30 | v1.3.1 | 修正版上線，驗收與回歸測試通過 |

## 檔案

| 檔案 | 內容 |
|---|---|
| `jinli.db` | SQLite 資料庫：19 萬筆轉動紀錄、1,500 位玩家、各版本理論值、數值規格表與實際設定 |
| `queries.sql` | 12 個查詢：資料品質檢查、日報、版本比較、找原因、設定核對、大獎、排名（視窗函數）、週報、七日回訪、玩家分群 |
| `金鯉躍門_日報_2026-09.xlsx` | 日報模板：原始資料 → 公式計算 RTP、z 值、p 值、觸發偏差、累計 RTP → 週報、版本比較、圖表 |
| `金鯉躍門_v1.3.1_驗收.xlsx` | 驗收文件：摘要（自動判定可否上線）、31 條測試案例、設定核對、數學驗收、Bug 清單、回歸測試 |
| `slot_math.py` | 遊戲數學引擎（與網頁版 `assets/slot-engine.js` 相同規則，理論 RTP 96.97%） |
| `build_data.py` | 產生 `jinli.db`（固定亂數種子，可重現） |
| `build_excel.py` | 從資料庫產生兩份 Excel |
| `run_queries.py` | 執行 `queries.sql` 並印出結果 |

## 怎麼使用

**直接看資料庫**：安裝免費的 [DB Browser for SQLite](https://sqlitebrowser.org/)，開啟 `jinli.db`，把 `queries.sql` 的查詢貼到「執行 SQL」分頁。

**用 Python 執行所有查詢**：
```bash
python run_queries.py          # 全部
python run_queries.py Q04 Q06  # 只跑指定的查詢
```

**重新產生資料與 Excel**（需要 numpy、openpyxl）：
```bash
python build_data.py
python build_excel.py
```

## 技術註記

- SQLite 預設沒有 `SQRT()` 和 `POWER()`，所以 SQL 用 z² 判斷警示（z² > 9 等同 |z| > 3），z 值交給 Excel 計算。
- 押注大小不同時，用「總押注 ÷ 20」換算成等效轉數再計算標準誤。
- 報表一律使用檢視表 `v_spins`，排除重複寫入與押注為 0 的錯誤紀錄。
- Excel 的計算欄位全部是公式，換掉「原始資料」就會重算；只有黃底藍字的儲存格需要手動輸入。
